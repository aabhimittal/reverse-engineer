# x86-64 assembly for reversers

You don't need to *write* assembly to reverse it, but you need a reading vocabulary of
about 30 instructions and three conventions.

## Analogy: a kitchen

- **Registers** are the cook's hands and the cutting board: tiny, fast, always in use
  (`rax`, `rbx`, `rcx`, `rdx`, `rsi`, `rdi`, `rbp`, `rsp`, `r8`–`r15`).
- **The stack** is a pile of plates: last on, first off (`push`/`pop`), and every function
  call puts its return address on top.
- **Memory** is the pantry: big and slow, addressed through brackets: `[rbp-0x20]`.

## The 30 instructions that matter

| Family | Instructions | Read as |
|---|---|---|
| Move | `mov`, `movzx`, `movsx`, `lea` | copy / zero- or sign-extend / *compute an address* (`lea` does no memory access!) |
| Arithmetic | `add`, `sub`, `imul`, `idiv`, `inc`, `dec`, `neg` | |
| Logic | `and`, `or`, `xor`, `not`, `shl`, `shr`, `sar`, `rol`, `ror` | `xor eax, eax` = set to 0; rotations + xor in a loop = crypto smell |
| Compare | `cmp`, `test` | set flags; `test eax, eax` = "is it zero?" |
| Branch | `jmp`, `je/jz`, `jne/jnz`, `jl/jg` (signed), `jb/ja` (unsigned) | the `if` statements |
| Calls | `call`, `ret`, `push`, `pop`, `leave` | |
| Strings | `rep movsb`, `rep stosb`, `repne scasb` | inlined `memcpy` / `memset` / `strlen` |
| Misc | `nop`, `endbr64`, `int3`, `syscall`, `cpuid`, `rdtsc` | `cpuid`/`rdtsc` near branches = anti-VM / timing checks |

## Calling conventions (who puts arguments where)

| Platform | Integer args | Return | Callee-saved |
|---|---|---|---|
| System V (Linux, macOS) | `rdi, rsi, rdx, rcx, r8, r9`, then stack | `rax` | `rbx, rbp, r12–r15` |
| Microsoft x64 (Windows) | `rcx, rdx, r8, r9` + 32-byte shadow space | `rax` | `rbx, rbp, rdi, rsi, r12–r15` |
| cdecl (32-bit) | stack, right to left | `eax` | `ebx, esi, edi, ebp` |

So on Linux, `lea rdi, [0x2004]` followed by `call puts@plt` is `puts("…string at 0x2004…")`.
rex prints that string as a comment for you.

## Recognising high-level shapes

```text
if/else          cmp … ; jcc else ; <then> ; jmp end ; else: <else> ; end:
for loop         init ; jmp cond ; body: … ; inc i ; cond: cmp i, n ; jl body
switch           cmp x, N ; ja default ; jmp [table + x*8]       ← indirect jump
function frame   push rbp ; mov rbp, rsp ; sub rsp, N  …  leave ; ret
stack canary     mov rax, fs:[0x28] ; mov [rbp-8], rax … xor … ; jne __stack_chk_fail
```

## Hands-on: read the crackme

```sh
rex disasm labs/build/crackme -F check_password
```

1. Find `call strlen@plt` and the `cmp` right after it: what length is required?
2. Find the loop (a block whose successor is itself or an earlier block): what's XORed with what?
3. The XOR key is a constant operand; the expected bytes are referenced as a string
   (rex shows it). XOR them to recover the password.

## Classic tools

`objdump -d -M intel`, `gdb` with `set disassembly-flavor intel`, Ghidra's Listing view,
radare2 `pdf @ sym.check_password`, the Compiler Explorer (godbolt.org) to see what C becomes.

## Exercises

2. Why does `lea rax, [rdi+rdi*2]` compute `rdi*3` without touching memory?
